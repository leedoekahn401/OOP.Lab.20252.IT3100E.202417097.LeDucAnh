1. Compare Swing and AWT elements.
- The main difference in the structure of Swing and AWT containers lies in the following:
  + AWT: Main top-level containers include Frame, Dialog, and Applet objects. Components can be directly added to these containers.
  + Swing: The main top-level containers include JFrame, JDialog, and JApplet objects. Components cannot be directly added to the container; rather, components have to be added to the content pane of the container (java.awt.Container).

- AWT components' class naming convention compared to that of Swing components' classes:
  + AWT: Class names do not contain any special characters but rather follow naming conventions like Button, TextField, and Label.
  + Swing: Naming of class names uses a character 'J' as a prefix to the component name. For instance, JButton, JTextField, and JLabel classes.

2. What happens when you don't update for them to catch (the PlayerException in the Aims class)?
- Being a custom exception class extending the java.lang.Exception class, failure to use a try-catch statement in catching the exception or declaring throws in the method where the exception occurs means the code would fail the compile-time test and generate a compilation error in accordance with Java Compiler rules.
- However, if the exception were a RuntimeException, unhandled at runtime would cause the application to crash. When used in conjunction with the user interface, this means that the UI may become unresponsive or shut down abruptly, thus negatively affecting the application experience. Capturing the exception provides an opportunity to present an alert to the user by use of a message dialog box like JOptionPane.
